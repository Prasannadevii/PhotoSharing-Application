HOW IT WORKS

From your browser to the cloud

Every upload follows the same five steps.

Sign in

Cognito's hosted page signs you in. The browser receives a secure token.

Request an upload link

The site asks API Gateway and Lambda for a short-lived, one-time upload URL.

Upload to S3

Your browser sends the photo straight to the private S3 bucket.

Save the details

An S3 event triggers Lambda, which stores the photo's details in DynamoDB.

Show the gallery

The site fetches your photo list and displays each one with a private view link.

THE CLOUD STACK

AWS services behind the scenes

👤

Amazon Cognito

Handles sign-in and issues the tokens used to call the API.

⇄

Amazon API Gateway

Exposes the upload-url and photos endpoints, protected by your sign-in token.

λ

AWS Lambda

Creates upload links, records new photos and returns your photo list.

▣

Amazon S3

Stores the image files in a private bucket.

▤

Amazon DynamoDB

Keeps each photo's title, file name, location and upload time.

🔔

Amazon SNS

Planned. Will send notifications about new activity.

BUILT WITH

Simple, readable code

The frontend is three kinds of files: HTML for structure, CSS for design and animation, and JavaScript for sign-in, uploads and the gallery. Sign-in uses the OAuth authorization code flow with PKCE, and every piece of text from the server is escaped before it is shown.

GOOD TO KNOW

A few things to expect

  • Sign in before uploading. Guests can browse the site but cannot save photos.
  • New photos can take a few seconds to appear while the cloud finishes processing them.
  • Remove hides a photo from this view only. It does not delete the file from cloud storage.
  • This is a learning project, so features will keep growing.
